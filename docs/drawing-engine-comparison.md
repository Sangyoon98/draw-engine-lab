# 드로잉 구현 3종 비교 — Ink API / Canvas / NDK GL
(R&D: Ink API 조사 보강용)

## 1. 개요
삼성노트식 필기/드로잉을 세 방식으로 구현해 비교한다.
- 전제: **삼성노트는 자체 C++(NDK) 엔진**으로 구현(역공학 분석 문서 참고). 세 버전은 전부 **클린룸**(삼성 코드 복제 아님).
- 공통 기능: 펜 여러 종 · 6색 · 굵기 4단 · 획/픽셀 지우개 · 되돌리기/다시/전체삭제 · 핀치 확대·이동.

## 2. 버전별 정의/구현

### Ink API (`:feature-ink`)
- **정의**: Google 공식 Jetpack Ink API로 구현.
- **구현**: `InProgressStrokes`(wet ink) + `CanvasStrokeRenderer`(dry). 스톡 브러시(펜·마커·형광펜·점선). 저지연·스무딩·압력 가변폭을 **엔진이 내장 제공**.

### Canvas (`:feature-canvas`)
- **정의**: **스마트러닝 렌더 방식 + 삼성노트식 펜 기능** 하이브리드.
- **구현**: `pointerInput`(입력) + `Canvas`(렌더) 직접. 펜 6종 동역학 직접(스플라인 스무딩·속도 관성·획끝 테이퍼). **비트맵 베이킹**(완료 획을 비트맵에 구워 매 프레임 1장 blit → 획 수와 무관하게 빠름).

### NDK GL (`:feature-nativegl`)
- **정의**: 역공학으로 본 **삼성 구조를 직접 추측 설계**(NDK 내부 코드는 확인 불가 → 추측 클린룸).
- **구현**: Kotlin `GLSurfaceView`(surface·EGL) → JNI → **C++ 스트로크 엔진**(스무딩·펜별 동역학·테셀레이션) → **GLES2 셰이더** 렌더. 확대는 셰이더 뷰 변환(scale/offset), 터치는 월드좌표 변환.

## 3. 장단점 비교

| 항목 | Ink API | Canvas (하이브리드) | NDK GL |
|---|---|---|---|
| 필기감·모션 | ★★★ 최상(엔진) | ★★ 약간 아쉬움 | ★★ 약간 아쉬움 |
| 저지연 | 내장(자동, HW 의존) | 직접(미구현) | GPU 렌더로 양호 |
| 호환성 | △ 구형/저사양 약함 | ★ 최대(전 기기·OS) | ★ 좋음(GLES2 광범위) |
| 획 많을 때 | 좋음(엔진) | 베이킹으로 빠름 | ★ GPU라 빠름 |
| 확대 품질 | 선명(벡터) | **깨짐(래스터 베이킹)** | **선명(GPU 벡터)** |
| 메모리 | 좋음 | 비트맵 고정 + 스택 | ★ C++로 효율 |
| 기능 범위 | △ alpha라 적음 | 자유(직접) | 자유(직접) |
| 구현 비용 | ★ 적음(갖다 씀) | 중 | △ 큼(C++) |
| 안정성 | △ alpha(미성숙) | ★ 검증된 방식 | 직접 검증 필요 |

## 4. 지우개 로직 비교 (획 제거 / 픽셀 제거)

| 버전 | 획지우개(object) | 픽셀지우개(pixel) | 메모리 영향 |
|---|---|---|---|
| Ink | `ops`에서 StrokeOp **실제 제거** | `ClearOp` **추가**(BlendMode.Clear) | 획=회수 / 픽셀=누적(undo용) |
| Canvas | `strokes`에서 **실제 제거** | 흰 Clear 획 **추가**(비트맵에 베이크) | 획=회수 / 픽셀=누적 |
| NDK GL | C++ `vector`에서 **실제 제거** | 흰 불투명 획 **추가**(위에 덧칠) | 획=회수 / 픽셀=누적 |
| *참고: 스마트러닝* | **없음** | PorterDuff.CLEAR(비트맵) + 커맨드스택 **append** | **스택 누적(메모리 이슈)** |

- **획지우개**: 세 버전 모두 **스택에서 실제 제거**(메모리 회수) → 스마트러닝의 "지우기도 append라 쌓임" 문제를 해결.
- **픽셀지우개**: 세 버전 모두 **"지우는 마크 추가(append)"** 방식(진짜 제거 아님) — undo 지원을 위한 의도적 선택이라 누적됨.

## 5. 결론 / 권고
- **Ink API** = 필기감·편의 최상, 구형 지원 약함 + alpha(미성숙)가 약점.
- **Canvas** = 호환성·안정 최강, 베이킹으로 빠름, 대신 확대 시 품질 저하(래스터).
- **NDK GL** = 품질 + 호환 + 확대 선명 + 성능의 **균형**, 대신 C++ 유지비.
- **권고(스마트러닝 관점)**: 당장은 Canvas(검증·전 기기)가 합리적. 필기 품질이 핵심 가치가 되면 NDK(전 기기+품질, 투자 필요) 또는 Ink(신형 타겟·정식 안정화 후). Ink는 정식화 전까지 프로덕션 전환은 성급.
